## 1. Project Context

**Devotional Journal** is a bilingual (EN/ES) Bible study web app for men. Users journal, reflect on scripture, track streaks, and follow structured reading plans.

The **Plan Builder** lets users create their own multi-day reading plans — either generated by AI or built manually day-by-day. Admin users can publish plans publicly.

### Tech Stack

| Layer      | Stack                                           |
|------------|------------------------------------------------|
| Backend    | Django 5 + DRF, PostgreSQL, Celery + Redis     |
| AI         | Ollama (local) or Anthropic Claude (cloud)      |
| Frontend   | React 18 + TypeScript, TanStack Query, Tailwind |
| Deploy     | Docker Compose on Ubuntu VPS, Nginx reverse proxy |

## 2. Data Model

### `ReadingPlan` — `backend/apps/plans/models.py:11-65`

```
id              UUID (PK)
title_en        CharField(200)
title_es        CharField(200, blank)
description_en  TextField
description_es  TextField(blank)
duration_days   PositiveIntegerField
category        CharField(20) — general|fatherhood|leadership|recovery|marriage|faith
is_premium      BooleanField (default False)
is_active       BooleanField (default True)
is_public       BooleanField (default False)  ← NEW — controls visibility
created_by      FK → User (nullable, SET_NULL)
created_at      DateTimeField (auto)
```

**Visibility rule:** `PlanListView` returns plans where `is_active=True AND (is_public=True OR created_by=request.user)`.

Admin (`is_staff`) can set `is_public=True` when saving. Non-staff always get `is_public=False`.

### `ReadingPlanDay` — `models.py:67-93`

```
plan                FK → ReadingPlan (CASCADE)
day_number          PositiveIntegerField
passages            JSONField — list of string refs, e.g. ["Romans 8:1-17", "Psalm 23"]
theme_en            CharField(200, blank)
theme_es            CharField(200, blank)
reflection_prompts_seed  TextField(blank) — used as seed for LLM prompt generation during reading
```

**Constraint:** `unique_together = ["plan", "day_number"]`

### `UserPlanEnrollment` — `models.py:95-127`

Tracks a user progressing through a plan. `current_day` increments via `AdvanceDayView`. `completed_at` is set when `current_day >= duration_days`.

## 3. API Endpoints

All under `/api/v1/plans/`. All require authentication (JWT).

| Method | Path | View | Purpose |
|--------|------|------|---------|
| GET    | `/`                       | `PlanListView`         | List visible plans (public + user's own) |
| POST   | `/generate/`              | `PlanGenerateView`     | AI-generate plan draft (NOT saved to DB) |
| POST   | `/save/`                  | `PlanSaveView`         | Save any plan (AI or manual) after review |
| GET    | `/<uuid>/`                | `PlanDetailView`       | Full plan with all days |
| DELETE | `/<uuid>/delete/`         | `PlanDeleteView`       | Delete own non-public plan |
| POST   | `/<uuid>/enroll/`         | `EnrollView`           | Start a plan |
| GET    | `/enrolled/`              | `EnrolledPlansView`    | List user's enrollments |
| GET    | `/enrolled/<uuid>/today/` | `TodayReadingView`     | Get current day's reading |
| POST   | `/enrolled/<uuid>/advance/` | `AdvanceDayView`     | Mark day done, advance |

Also:

| Method | Path | View | Purpose |
|--------|------|------|---------|
| GET | `/api/v1/prompts/ai-status/` | `AIStatusView` | Check if LLM backend is reachable |

### Generate endpoint shape

**Request:**
```json
{
  "topic": "Covenant faithfulness through Deuteronomy",
  "duration_days": 7,
  "category": "faith",
  "anchor_passages": ["Deuteronomy 29:1-9"]
}
```

**Response (200):** Raw plan draft — NOT saved. Frontend presents this for review.
```json
{
  "title_en": "...",
  "title_es": "...",
  "description_en": "...",
  "description_es": "...",
  "duration_days": 7,
  "category": "faith",
  "days": [
    {
      "day_number": 1,
      "passages": ["Deuteronomy 29:1-9"],
      "theme_en": "The covenant remembered",
      "theme_es": "El pacto recordado",
      "reflection_prompt": "Where have you seen God keep a promise when you couldn't?"
    }
  ]
}
```

### Save endpoint shape

Accepts the same JSON shape as generate returns (user may have edited title, themes, etc. in the preview). Creates `ReadingPlan` + `ReadingPlanDay` rows.

## 4. AI Service

`backend/apps/prompts/services.py`

### Architecture

```
PromptService (ABC)
├── _PLAN_SYSTEM_PROMPT (class var — template with {duration_days} slot)
├── _parse_plan_response(text) → dict|None (strips markdown fences, finds JSON)
├── generate_reading_plan(...) → dict|None (abstract)
│
├── OllamaPromptService
│   └── generate_reading_plan() — POST /api/generate, format: "json"
│
└── AnthropicPromptService
    └── generate_reading_plan() — POST /v1/messages
```

### System Prompt Key Constraints
- Must return exactly `{duration_days}` days
- Each day: `day_number`, `passages[]`, `theme_en`, `theme_es`, `reflection_prompt`
- Passages must progressively build
- Anchor passages must appear in the output
- No religious jargon, masculine tone
- Reflection prompts must be specific (no generic "what does X mean to you")

### Known Weaknesses
1. **No schema validation on AI output** — if LLM returns `theme` instead of `theme_en`, it passes through silently
2. **No retry logic** — one shot, if it fails, user sees error
3. **Day count enforcement is ≥ not ==** — if AI returns 10 days for a 7-day plan, we truncate silently with `days_data[:duration_days]`. If it returns fewer, we reject.
4. **120s timeout** — long plans (28-40 days) on weaker Ollama models may time out

## 5. Frontend

### `PlanBuilderModal` — `frontend/src/components/PlanBuilderModal.tsx`

Three-screen modal:

**Screen 1: Form**
- AI/Manual toggle (pill switcher)
- AI mode: checks `GET /prompts/ai-status/` on open → green/yellow banner
- AI mode: topic textarea + category + duration + anchor passages (chip input)
- Manual mode: title textarea + category + duration → "Set Up Days →"
- AI mode: "Generate Plan" → transitions to Screen 2

**Screen 2: Generating** (AI only)
- Spinner + 5-step progress checklist (fake timed progression every 18s)
- "This can take 1-2 minutes" disclaimer

**Screen 3: Preview**
- Editable title + description
- Accordion list of all days, each expandable with:
  - **Passages** (comma-separated input)
  - **Theme** (text input)
  - **Reflection Prompt** (textarea)
- Manual mode: Day 1 auto-expanded, "No passages yet — tap to add" hint
- AI mode: header says "Review Your Plan / Edit anything before saving"
- Manual mode: header says "Build Your Plan / Fill in passages for each day"
- Footer: "← Regenerate" (AI) or "← Back" (Manual) + "Save Plan"

### `PlansPage` — `frontend/src/pages/PlansPage.tsx`

- "Build a Plan" button in header → opens modal
- Plan grid cards (no "My Plan" badge yet — **gap**)
- Plan detail modal (read-only, no edit/delete for owned plans — **gap**)
- Active enrollments section with progress bars
- Category filter pills
- Today's Reading modal with passage links → ScriptureReader

### API Types — `frontend/src/api/plans.ts`

```typescript
interface ReadingPlan {
  id: string; title: string; description: string;
  duration_days: number; category: string;
  is_premium: boolean; is_public: boolean; is_owned: boolean;

```

`is_owned` is computed server-side by the serializer (`created_by_id == request.user.id`).

## 8. Deployment

```bash
# Local: from project root
ssh -i ~/.ssh/windsurf-Rincewind.pem curlyphries@curlyphries.net

# On server:
cd /home/curlyphries/projects/devotional-journal
git pull origin master

# Build (note: uses docker-compose v1 with --env-file)
docker-compose -f docker-compose.prod.yml --env-file .env.prod build dj-backend dj-frontend

# Stop/rm old containers (workaround for docker-compose 1.29.2 ContainerConfig bug)
docker stop devotional-journal_dj-backend_1 devotional-journal_dj-frontend_1
docker rm devotional-journal_dj-backend_1 devotional-journal_dj-frontend_1

# Bring up
docker-compose -f docker-compose.prod.yml --env-file .env.prod up -d dj-backend dj-frontend

# Run migrations if needed
docker exec devotional-journal_dj-backend_1 python manage.py migrate
```

**Known deploy quirk:** `docker-compose 1.29.2` on the server throws `KeyError: 'ContainerConfig'` when recreating containers with newer Docker image formats. Workaround: always stop + rm containers before `up -d`.

## 10. Testing Checklist

Before declaring this feature complete, verify:

- [ ] AI mode: generate → preview → edit title → save → appears in plan list
- [ ] AI mode: generate with anchor passages → verify anchors appear in output
- [ ] AI mode: AI unreachable → yellow warning → Generate button disabled → Manual works
- [ ] Manual mode: create 7-day plan → fill in passages for 3 days → save → enroll → today's reading shows correct day
- [ ] Plan visibility: user A creates plan → user B cannot see it → admin sets is_public → user B sees it
- [ ] Delete: user can delete own non-public plan → gone from list
- [ ] Rate limit: hit generate 4 times in 1 hour → 4th rejected with 429
- [ ] Edge: 40-day AI plan → check timeout handling → error message is clear
- [ ] Edge: AI returns malformed JSON → clean error, not a blank/broken plan
- [ ] Bilingual: user with language_preference=es → plan titles/themes render in Spanish (for AI-generated plans)
